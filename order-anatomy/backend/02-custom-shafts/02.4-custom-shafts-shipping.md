# Shipping: lasts to FeetF1rst, finished work back to the partner

An order travels twice:

| Leg | System name | What travels |
| --- | --- | --- |
| Partner → FeetF1rst | `partner_to_admin` | The customer's lasts or sample, when the partner has no 3D files |
| FeetF1rst → partner | `admin_to_partner` | The finished shaft or shoe |

Each leg is a row in `custom_shafts_shipping`. FedEx makes the labels. The FeetF1rst address on every label is FeetF1rst, Pipen 5, 39031 Bruneck (BZ), Italy (`RECEIVER` in `utils/fedex.service.ts`).

## The shipment row (`custom_shafts_shipping`)

| What it means | Column | Notes |
| --- | --- | --- |
| Which leg | `shipping_flow` | `partner_to_admin` or `admin_to_partner` |
| Price type for the partner | `shipping_type` | Express or Standard. Never overwritten by FedEx. |
| FedEx service really used | `fedex_service` | Set when the label is made, corrected by the tracking job |
| Several orders in one parcel | `isGrouped` | Default no |
| Handled by the automatic job | `isAutomated` | Default yes. Turned off when FedEx fails three times or the group was shipped by hand. |
| Label PDF | `pickup_label` | FedEx or a file the admin uploaded |
| When the label was made | `label_created_at` | |
| Tracking number | `fedex_tracking_number` | |
| Number of orders in the parcel | `quantity` | Default `1` |
| Planned sending day | `shipping_time` | For partner → FeetF1rst, the partner's sample sending date |
| What FeetF1rst charges the partner | `shipping_cost` | From `shipping_pricing` |
| What FedEx charges FeetF1rst | `fedex_shipping_cost` | Set by the tracking job when FedEx reports delivery |
| Address | `postalCode`, `street`, `city`, `state`, `country` | Pickup address, or the partner's delivery address |
| Delivery note PDF | `delivery_note` | For FeetF1rst → partner |
| Main order | `custom_shafts_id` | The order that owns the row ("anchor") |
| All orders in the parcel | `linked_custom_shafts` | Orders whose `custom_shafts_shipping_id` points here |
| FedEx label attempts | `fedex_try_count`, `fedex_status` | `pending`, `success`, `failed` |
| Delivered | `shipping_status`, `delivered_at` | `panding` / `delivered`, and the real FedEx delivery time |
| Tracking text | `fedex_track_status`, `fedex_track_problem`, `estimated_delivery_at`, `picked_up_at` | Updated by the tracking job until delivered |
| Invoice and delivery note numbers | `shipping_delivery_note` | One row per shipment |

An order is linked to a shipment in two ways: the shipment's main order (`custom_shafts_shipping.custom_shafts_id`), and the order's own link (`custom_shafts.custom_shafts_shipping_id`). Cancelling cleans up both (see `02.3-custom-shafts-status-and-payment.md`).

### Delivery note and invoice (`shipping_delivery_note`)

| Column | What it is |
| --- | --- |
| `delivery_note_pdf`, `delivery_note_number` | The Lieferschein and the number printed on it, e.g. `1290` or `1290 - 1292` |
| `delivery_invoice_number` | Starts at `1000`, next number on first save, never changes |
| `delivery_invoice` | The uploaded invoice file |
| `delivery_date` | First invoice save. Payment is due 7 days later. |

### Same-day groups (`package_group`)

When an order gets a delivery date, it joins the partner's group for that day (`resolveOrCreatePackageGroupId`), unless `withgroup=true` is sent. The group has `started_at` and `finished_at`. FeetF1rst → partner parcels are built from these groups.

### Prices (`shipping_pricing`)

The admin saves `express_price` and `standard_price` (`POST /v3/admin-order/shipping-pricing/create`). Any login can read them (`GET /v3/admin-order/shipping-pricing/get`).

## Partner → FeetF1rst

### At order time

The choice is `lest_sending_type` on the order (see `02.1-custom-shafts-shaft-and-complete-shoe.md`).

| Choice | What happens |
| --- | --- |
| 3D files sent | The order starts at `lasts_received`; no lasts need to travel |
| `feetf1rst_shipping` (ship with others) | A grouped `partner_to_admin` row, no label yet. The partner's grouped pickup takes it later. |
| `self_shipping` | A single `partner_to_admin` row at the order's pickup address, and a FedEx label in the background. When it works, the partner gets the label by e-mail ("label ready"). When it fails, the partner gets a "label failed" message. |
| `shipping_id=…` | The order joins that shipment |
| `shipping_order_id=…` | A new shipment is made with this order as the main order, and the listed orders join it |
| `createLabel=yes` with one of the two above | The FedEx label is made in the background. The answer says `processing`. |
| Nothing chosen and no pickup address | No shipment. The admins get the order e-mail without shipping details. |

When the order joins a shipment without a label and the joining fails, the answer is an error, but the order, its billing line, and the higher open amount already exist.

## FeetF1rst → partner

### How a parcel is made

1. When a shaft or complete shoe reaches `Qualitätskontrolle`, it gets an `admin_to_partner` row or joins one for its same-day group (`ensureAdminToPartnerShippingOnQualitätskontrolle`). The job below also does this for any such order that has none.
2. A missing address is filled from the partner's store location (`fillAdminToPartnerShippingFromStoreLocation`).
3. The job waits until no live order of the same-day group is still before quality control.

### The automatic job (`cron/admin_to_partner_grouped_shipping.ts`)

It runs every minute. For each grouped, automated `admin_to_partner` row:

| Step | What it does |
| --- | --- |
| Wait | First attempt only 60 minutes after the row was made. Retries 1 minute after the last attempt. |
| Already shipped by hand | No label and every order already `Versandt` or `Ausgeführt`: the row leaves the job |
| Address | Must be complete and safe for shipping, and the country must be valid |
| Delivery note | A Lieferschein PDF is made and saved (`saveLieferscheinOnShipping`) |
| Price | Unit price for the type × number of orders. Every order gets `shipping_type2`. |
| Label | `generateAdminToPartnerLabelForShipping` |
| After the label | Orders still in `Qualitätskontrolle` become `Versandt` with `shipping_time`. Their shoe order steps are completed. No status history is written. |
| Failure | Up to 3 attempts. After the third, `fedex_status: failed`, the row leaves the job, and the admins get "FedEx-Versandlabel … fehlgeschlagen … Bitte Adresse prüfen und das Label manuell erstellen." |

## FedEx tracking job (`cron/fedex.custom-webhook.ts`)

Runs at 08, 10, 12, 14, 16, 17 and 18 o'clock, Berlin time. For each shipment with a tracking number that is not delivered yet, it reads FedEx tracking and saves the status text, problems, estimated delivery, and pickup time. When FedEx says delivered, it saves `delivered_at` and the FedEx cost, and sets live orders that are not done yet to `Ausgeführt`. It writes no status history and does not change the billing lines.

## A worked example: physical lasts there and back

The shop "Orthopädie Weber" in Munich has no 3D files for a shaft order. It will post the plaster lasts itself.

1. The shop orders with `lest_sending_type: self_shipping`, its pickup address in Munich (`country: DE`), `shipping_type1: Standard`, and a sample sending date of 7 October.
2. The order is saved with `status: Bestellung_eingegangen`, `last_status: Unangekommen`, no production start, and `sample_sending_date` 7 October.
3. A `partner_to_admin` row is made: not grouped, the Munich address, `shipping_type` Standard, `shipping_cost` from `shipping_pricing.standard_price`, `shipping_time` 7 October. In the background FedEx makes the label from Munich to Bruneck, and the shop gets the "label ready" e-mail.
4. The parcel arrives in Bruneck. The admin marks the last as arrived (`last_status: Angekommen`). The order moves to `lasts_received`, and the production clock starts that day: `production_start_date`, `deliveryDate`, and `delivery_length` are calculated from the shaft's working days.
5. After production the admin sets `Qualitätskontrolle`. The order gets or joins an `admin_to_partner` row for its same-day group. The address comes from the shop's store location when none is set.
6. When no order of the same-day group is still before quality control, and at least 60 minutes after the row was made, the job makes the Lieferschein, sets the price (unit price × number of orders), and asks FedEx for the label.
7. The label works: the order becomes `Versandt` with `shipping_time` now, and the shoe order's steps are completed.
8. At one of the tracking runs FedEx reports "delivered". The row gets `delivered_at` and the FedEx cost, and the order becomes `Ausgeführt`. No status-history line is written for steps 7 and 8, and the billing line stays `panding` (problem 12 in `02.5-custom-shafts-problems.md`).
