# Counts, late orders, holidays, and working days

The admin dashboard shows cards such as "open orders", "late", and "shipped this month". This file says how each number is counted, and how holidays and working-day settings move delivery dates.

The production clock itself (working days → `deliveryDate` and `delivery_length`) is described in `02-custom-shafts.md`.

## The base rule

Almost every count leaves out cancelled orders, neutral orders, and drafts:

- `order_status` is not `canceled` and not `neutral`
- `order_type` is empty or not `draft`

Below this is called "live orders".

## The cards on the admin's Partnerbestellungen page

`GET /v3/admin-order/calculation/get-calculation-data`, admin only, gives all numbers at once (`module/v3/admin_order/calculation/calculation.controllers.ts`). Clicking a card opens a list from `/v3/admin-order/calculation-info/*` (`module/v3/admin_order/calculation_info/`), which uses the same filter. The admin dashboard calls them from `apis/subAdmin/partnerbestellungen/partnerbestellungenApis.js` on `dashboard/partnerbestellungen`.

| Card | Number in `get-calculation-data` | List address | Which live orders |
| --- | --- | --- | --- |
| Open orders | `open_orders` | `get-open-orders-list` | Status not `Versandt` and not `Ausgeführt` |
| Order received | `bestellung_eingegangen` | `get-new-orders` | Status `Neu` or `Bestellung_eingegangen` |
| In production | `in_production` | `get-in-production` | Status `In_Produktiony` |
| Waiting for lasts | `waiting_for_last` | `get-waiting-for-last` | Open, shaft or complete shoe, no production start |
| Not sent to production | `open_orders_not_sent_to_production` | `get-open-orders-not-sent-to-production` | Status `Neu` or `In_Bearbeitung`, in the five main categories |
| Late | `late_orders` | `/v3/admin-order/track/get-latest-orders` | See "Late" below |
| Due in the next 3 days | `delivery_date_in_next_3_days` | `get-delivery-date-in-next-3-days` | Open, five main categories, production start + `delivery_length` from today up to (not including) today + 3 |
| Finished this month | `finished_this_month` | `get-finished-this-month` | `delivered_at` in the current month. No status check. |
| Shipped this month | `shipped_this_month` | `get-shipped-this-month` | Status `Versandt`. **No date check**: every order that is still `Versandt` counts, whatever the month. |

| Unread messages | `unread_messages` | — | Sum of `chat_admin_unread` |

The five main categories are test shoe, shaft, complete shoe, sole, and last. Sample and insole orders are left out of the late and due-soon numbers.

The list addresses take `limit` (default 20), `cursor`, and `search`. They have no login check (problem 7 in `02.5-custom-shafts-problems.md`). `get-revenue-orders` lists live orders created between `startDate` and `endDate` (Berlin time, default this month); it gives no sums.

## Late

An order is late when its planned end (production start + `delivery_length` days) is before today and it is not finished yet. "Finished" means `Versandt` or `Ausgeführt`; a test shoe also counts as finished when it is `Warten_auf_Anprobe`.

The rule exists in four versions:

| Where | Needs a production start | Categories | Shown on |
| --- | --- | --- | --- |
| `get-calculation-data` and `track/get-latest-orders` / `count-latest-orders` | Yes | Five main | Partnerbestellungen "Late" card and its list |
| `calculation-info/get-late-orders` | Yes | Five main | No screen |
| `calculation/count-all-late-orders` | Yes | All | No screen |
| `statistics/get-calculations` | No: uses the creation date when there is no start | All | manage-order page "Late" card |

So the late card on `partnerbestellungen` and the late card on `manage-order` can show different numbers for the same day. An order waiting for physical lasts counts as late only on the manage-order card.

"In production" also means two things: `In_Produktiony` on `partnerbestellungen`, but every status except `Neu` and `Ausgeführt` on `manage-order` (which includes `Bestellung_eingegangen` and `Versandt`).

## Working days per kind of order (`custom_shafts_delivery_dates`)

One row per category with `day` (working days) and `production_cost`.

| Address | Logins | What it does |
| --- | --- | --- |
| `POST /custom_shafts/delivery-dates/manage` | Partner, admin, employee | Creates or updates the rows. The admin dashboard calls it (`apis/orderApis.js`). Open orders are not re-planned. |
| `GET /custom_shafts/delivery-dates/get` | Partner, admin, employee | Reads them. The Partner Dashboard uses it to estimate dates before ordering. |
| `GET /custom_shafts/delivery-dates/get-with-estimate` | Partner, admin, employee | The same with an estimated date |
| `POST /custom_shafts/delivery-dates/suggest-orders-after-3-days` | Partner, employee | Body `date`. The shop's live orders whose `deliveryDate` is exactly 3 days after that date, with their package rows. The Partner Dashboard calls it (`apis/customShaftsApis.ts`). |

## Holidays and vacation (`holyday_and_vacation`)

One row per blocked day: `type` (`holiday` or `vacation`) and `date`. A day can have one holiday and one vacation. Blocked days apply to every shop.

| Address | Logins | What it does |
| --- | --- | --- |
| `POST /custom_shafts/delivery-dates/add-holyday-and-vacation` | Partner, admin, employee | Adds a day (saved at noon) and re-plans open orders |
| `GET /custom_shafts/delivery-dates/get-holyday-and-vacation` | Partner, admin, employee | Lists days |
| `POST /custom_shafts/delivery-dates/undo-holyday-and-vacation` | Partner, admin, employee | Deletes days and re-plans open orders |

The admin's holiday window (`components/dashboard/ManageOrders/HolidayVacationModal.jsx`) uses them. There is no edit; a day is removed and added again.

### Re-planning after a holiday change (`recalcOpenOrdersForBlockedDateChange`)

It runs inside the same request, after the day was saved or deleted.

1. Load the working days of every category. If none are set, stop.
2. Take every live order that has a `deliveryDate` and a category and is not finished (same "finished" rule as late).
3. For each order: start = production start, or the creation date when there is none. Count the category's working days from the start, skipping weekends and every blocked day.
4. When the day or the length changed, save the new `deliveryDate` and `delivery_length` (calendar days). Saved in groups of 50.
5. The answer carries `delivery_recalc: { checked, updated }`. If re-planning fails, the answer is still `200` with `delivery_recalc: null`; the holiday change stays.

Orders without `deliveryDate` are not re-planned: the test shoe and the automatic last order (problem 11), and orders waiting for lasts that were saved without a date.

A date the admin changed by hand is also overwritten, because the re-plan always counts from the category's working days (problem 20).

## A worked example: one holiday

Shaft `10023` started on Monday 5 October 2026 with 10 working days: `deliveryDate` 19 October, `delivery_length` 14 (see `02.1`).

1. The admin adds Friday 9 October as a holiday.
2. The re-plan counts again from 5 October, skipping 10, 11 (weekend) and 9 October: the tenth working day is now Tuesday 20 October.
3. `10023` gets `deliveryDate` 20 October and `delivery_length` 15. The answer says `delivery_recalc: { checked: …, updated: … }` with `10023` among the updated ones.
4. On 21 October, if `10023` is still `In_Produktiony`, it is late on both cards. On 20 October it is not yet late.
